# Аудит моделей: этап 1–4

`audit_model(handle, report_dir, include_excluded=false, max_nodes=10000)` читает
дерево без перестроения, сохранения и переключения активного документа. Нужны
явный API7 handle документа и новая абсолютная папка. Компактный итог возвращается
клиенту; status.json, journal.jsonl и details.json остаются на диске.
`read_audit_report(report_dir, offset, limit)` читает прогресс и до 200 записей,
также после потери клиентского контекста. Задание синхронное, ограниченное;
после падения сервера нужен новый аудит. Это не отдельный возобновляемый процесс.

Проверяются файлы, состояния IFeature7, собственные тела каждого источника,
вхождения и отдельные коллекции диагностик, отсутствующие в операционном дереве.
История читается в контексте первого вхождения каждого источника. Общий
IFeature7.FeatureType=o3d_entity уточняется через IModelObject.ModelObjectType.
Объекты дерева различаются нативным Reference в пределах источника. COM-обёртки
удерживаются до конца обхода. Топология не заменяет параметрическую историю.

Вхождение адресуется индексным путём [2, 0] в конкретном снимке. После изменения
состава путь обнаруживается заново; одинаковое имя или файл не идентифицируют
вставку. Матрицы SDK содержат перенос в элементах 12–14:
local_to_root = local_to_parent × parent_to_root. GetGabarit уже учитывает
положение в родителе: envelope преобразуется только матрицей родителя.
Повернутый envelope может быть больше точного габарита.

## Результаты

- passed: пройдена названная проверка в указанной области.
- failed: ObjectError, недействительный объект, разрыв связи, ошибка решателя.
- inconclusive: проверка неполна, не выполнена, ограничена лимитом или недостоверна.
- Записи warning: требуется обновление/перестроение или эскиз недоопределён.
- Записи inactive: объект исключён или откачен.

Недоопределённый эскиз требует решения об ограничениях; массовая фиксация
не применяется. Valid=false пустой папки сопряжений не является ошибкой тела.
NeedRebuild/TreeNeedRebuild не используются как признаки неисправности.
Чистое кэшированное дерево не доказывает независимое перестроение, точность BRep,
монтажные зазоры или собираемость.

`check_collisions(handle, paths1, paths2, copy_root, assembly_as_one=true)` считает
точные пересечения двух групп. Пустая paths2 проверяет все выбранные paths1
между собой. Документ и все компоненты, включая исключённые, должны лежать
в copy_root. Сначала копируются и перепривязываются зависимости; одного SaveAs
A3D недостаточно. Не задавайте папку оригиналов как copy_root.
Удаляется только собственная временная диагностика, её количество сверяется
до/после. Документ не сохраняется; Changed может стать True. Перекрывающиеся
выборки [0] и [0, 1] и исключённые ветки отклоняются.
CollisionObject1/2 проверяются на IsSolid/GetGabarit. SDK может вернуть корневые
«пустые» тела; точная подпись пары остаётся неподтверждённой. Ноль при выборе
вложенных объектов — inconclusive: эквивалентность группе не установлена.
Резьбовые/сварные пересечения автоматически не разрешаются.

## Документы и производительность

open_document повторно использует канонический путь (reuse_existing) и проверяет
фактический ReadOnly. Существующие документы не присваиваются серверу; собственные
помечены owned_by_server. Закрытие отказывает при несохранённых изменениях без
явного discard_changes и освобождает связанные дескрипторы/определения/снимки.
list_documents сверяет реестр также после закрытия через интерфейс КОМПАС.
Повторное использование отклоняется с stale_handle. Advanced-дескрипторы без
установленной принадлежности консервативно сбрасываются при закрытии; scoped
дескрипторы других документов сохраняются.
Очередь ограничена 8 заданиями, включая выполняющееся. queue_full — отказ до
выполнения. Отмена не прерывает работающий COM-вызов, его слот занят до конца.
Все COM-объекты остаются на одном STA. list_entities возвращает snapshot_id:
передавайте его следующей странице. Проверяется UpdateStamp; снимок сбрасывается
при возможной мутации и закрытии. Область топологии — собственные тела документа.

## Приёмка

tests/test_audit.py проверяет состояния, гибридные тела, диагностики, лимиты,
преобразования, одинаковые имена, stale-реестры, страницы и отмену занятой очереди.
Живой сценарий: `uv run python scripts/validate_audit.py C:/absolute/new-test`.
Он проверяет пересечение цилиндров известного объёма, разнесение, вложенную
сборку с поворотом 180°, повторное открытие, удаление временной диагностики,
20 циклов без роста документов/дескрипторов, чужие изменения и хэш источника.
Результат — acceptance.json. Касание, малый зазор, допуски BRep, резьбовые
исключения и полная эквивалентность вложенной селекции группе ещё не подтверждены.
Производственные CAD и персональные журналы хранятся вне публичного репозитория.

## Пакетная работа с эскизами и ссылками

`inspect_sketches` читает линии, окружности, дуги и скопированные ограничения
через отдельные FRW в `copy_root/sketch-inventory`. Это сохраняемые снимки,
их Reference не идентифицирует объекты исходного эскиза. Источник не открывается
в режиме редактирования. Проверяются его Changed и ISketch.ConstraintsState
до/после. На проверенной установке даже BeginEditEx(true)/EndEdit переводил
определённость 1→2 без изменения кривых; поэтому этот маршрут для чтения исключён.

`constrain_sketch` по умолчанию возвращает план. Явное применение к одному
первоначально неограниченному эскизу создаёт одну базовую точку, совпадения,
выравнивания и управляющие координатные/диаметральные размеры. Замораживание
всех примитивов не применяется. Каждый исходный примитив сравнивается после
ограничений с точностью 0.000001 мм, включая направление и углы дуги. Геометрия
с существующими ограничениями или неподдерживаемыми кривыми отклоняется.
Нет автоматического отката: после отказа нужно закрыть собственную копию без
сохранения. Объём, тела, сохранение и повторное открытие проверяются отдельно.
Координатный план сохраняет текущий профиль, но не выводит технологические
формулы, касания и семейства типоразмеров. Иррациональные координаты могут
потребовать иной схемы: округление решателя на шестиграннике обнаружено
сравнением и не принимается как неизменная геометрия.

`rebind_component_sources` работает только с непосредственными компонентами
одной сборки. До применения проверяются явные старые/новые файлы и изоляция
дерева; после перестроения — все матрицы и ссылки. Непопавшая в состав замена
считается устаревшим планом. Подсборки готовятся снизу вверх. Проверка массы,
контуров и всех вложенных матриц остаётся частью приёмки. Не сохраняет и не
исправляет сопряжения; частичный отказ требует отбросить изменения копии.

`scripts/validate_sketches.py` проверяет сетку четырёх окружностей, скруглённый
контур и профиль с двумя радиусами: сохранение/повторное открытие, все кривые,
нативное состояние и изменение диаметра 10→12→10 мм с известной разностью
объёма 33π мм³. Дополнительно проверены горизонтальный и вертикальный пазы
с полуокружностями и изменение ширины 12→14→12 мм с разностью 3(16+13π) мм³.
Это отдельная проверка чтения без побочных изменений состояния.

`place_components` принимает явные индексы непосредственных вхождений, ожидаемые
и новые матрицы. Разрешены только жёсткие преобразования без масштаба и отражения.
Проверяются изоляция копий, исходные положения, ссылки и Fixed; положения остальных
вхождений должны остаться прежними. По умолчанию возвращается план без применения.
Метод не сохраняет документ и не решает произвольные сопряжения. На v25 изменение
принадлежащего компоненту API5 placement через InitByMatrix3D подтверждено чтением
матриц и отдельной приёмкой после сохранения/открытия с измерением тел. При этом
UpdatePlacement возвращал false: результат сохраняет этот код, а не маскирует его.
Поле persistence_verified=false требует отдельной проверки постоянства геометрии.
