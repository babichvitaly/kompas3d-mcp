# Authoring boundary proposal and offline regressions

These contracts describe a proposed general SDK API. They do not execute CAD,
query the VM, edit active project helpers, install a client or establish native
acceptance. The existing isolated SDK worktree contains only generic code and
synthetic fixtures. A successful oracle result is `consistent_offline_evidence`,
with `native_acceptance='pending'` and `mutation_performed=False`.

## Fresh occurrence binding after mutations

Proposed native API: `bind_row_geometry_owned(document, row_key, occurrence_key)`.
Accept a frozen key of occurrence **path + source/hash + placement matrix**, not
an earlier cached IPart7 wrapper. Resolve only within the verified owned document.
Native scope and ambiguity checks must run before any write.

Required sequence:

1. Finish SpecificationDescriptions.Add, tuning.Update or BaseObjects.Add as
   applicable. Treat that operation as an interface invalidation boundary.
2. Resolve the target occurrence anew by its full key **after** the boundary.
   Pass this new interface to IncludeGeometry.
3. Perform row.Update, then resolve by the full key again. Read row.Geometry and
   require exactly one entry whose Reference equals that fresh occurrence's
   Reference. Do not compare against a pre-Update cached interface.

`assess_occurrence_binding` checks a bounded receipt of this sequence, including
strictly ordered operation/lookup epochs. IncludeGeometry=True never substitutes
for the final exact binding. References may change across mutations; semantic
keys must not. Epoch claims are collector evidence, not proof that a native
lookup occurred. No automatic occurrence adoption or retry is proposed.

## Preserve autogenerated synchronization without weakening payload checks

Proposed explicit policy: `preserve_autogenerated_true`. Autogenerated 3D rows
can ignore assigning `SyncronizeWithProperties=False`: the immediate getter can
remain True. That fact does not itself mean the text or section was reset.
New code must preserve observed True rather than relying on disabling sync.
Keep `EditSourceObject=False` and check exact UUID, section and all expected text
columns immediately, after row.Update, after description.Update and on saved RO.

`assess_autogenerated_row` compares these payload observations exactly; it can
record an ignored legacy False setter separately. It rejects actual text/section
changes, Sync=False or EditSourceObject=True. Its two saved-row snapshots are
payload evidence only: independent RO session/hash/order evidence belongs to the
full saved-cycle contract, not this row-only oracle. The policy neither approves
manual rows nor changes automatic numbering settings.

## Material envelope versus the whole annotated view

GetObjectsGabarit(view) includes annotations. Adding leaders and later resolving
`?` into linked position text can change whole-view bounds without changing the
underlying material geometry. Never use that expanded envelope to redefine the
material target point.

Proposed capture API exposes separate `material_before/material_after` bounds
and projected-material geometry digest, plus whole-view snapshots. The immutable
view identity includes source/hash, view number/type, projection matrix, positive
scale, X/Y, angle and unfold state. Compare it before/after annotations. Keep the
anchor-selection bounds equal to the independent material envelope.

After **all** native writeback, recapture `final_whole` from the actual annotated
view. Its whole bounds/count/digest may legitimately differ from the pre-annotation
snapshot; they must then persist exactly through two distinct, ordered saved RO
observations of the sealed drawing. `assess_annotation_bounds` implements that
offline evidence check. It does not derive material bounds by subtracting guessed
leader envelopes or alter the existing ViewState inspection implementation.

## Recipe argv and missing-terminal reconciliation

`run-recipe` already uses an argv list with no shell. An outer launcher can still
corrupt arguments before they reach it, for example by sending JSON-escaped path
strings as literal shell arguments. Do not blindly replace doubled backslashes:
UNC prefixes, trailing slashes and legitimate literal arguments would be damaged.
A JSON display containing escaped slashes alone is not proof of corrupt argv.

`recipe_transport.encoded_recipe_command(python_executable, argv)` constructs a
proposed lossless transport: one JSON argv encoded as UTF-8/base64; a PowerShell
UTF-16LE EncodedCommand invokes an explicit Windows Python executable with that
payload. The Python bootstrap decodes argv and launches a list through Popen,
without shell, retries, timeouts or exception-time child termination. It preserves
UNC, drive paths, Unicode, spaces, empty arguments, quotes and trailing slashes.
It does not launch anything itself. Invoke its `powershell_argv` as a list in the
outer VM launcher; do not JSON-escape individual command-line paths again.

Synthetic tests execute the same Python bootstrap only on harmless host programs
and verify exact downstream argv. They also round-trip the encoded PS script and
literal-quote the Python executable. Actual PowerShell parsing, Windows native
argument conversion and prlctl transport are **not tested** here; Windows/VM
acceptance requires separate exclusive coordination. Base64 is encoding, not
secret protection; do not log payloads containing credentials.

If a recipe ran but its terminal cannot be read, `run-recipe` now explicitly
reports `phase='reconciliation_required'`, child PID, recipe_started, raw and
resolved terminal argument, and `retry_allowed=False`, while retaining the existing
unreported/failed status and exit-code distinction. It neither guesses a different
receipt nor restarts the mutation. Inspect the already-written receipt and verify
it separately. The original lease remains, preventing a second producer for that
terminal path. A regression counts child executions and verifies the actual
receipt without launching the recipe again.

No installed SDK/configuration, existing CAD files, application processes, VM
settings or publication state are changed by this checkpoint. Dynamic following,
package portability and native geometry correctness remain separate gates.

## Sequential binding executor checkpoint

`row_binding.bind_row_geometry_owned(expected_key, boundary_kind, adapter)` now
implements the callback order with a platform-independent injected adapter.
`RowBindingAdapter` defines the required ownership guard, explicit boundary,
fresh resolver, identity getters, inclusion/update calls and geometry readback.
It does not ship a native COM adapter or connect to any application.

The guard runs before each adapter call and at completion. The frozen semantic
key is copied for each resolver call. After the boundary, a fresh occurrence is
resolved and included; after row.Update, a second fresh occurrence is resolved.
Row UUID must persist and Geometry must equal the singleton second reference.
An Update=False observation may pass only with that exact readback. Missing
adapter callbacks fail before mutation. No save, close, fallback or retry occurs.
Failure receipts identify the phase and completed callbacks; mutation_possible
is marked before entering a mutating callback, including uncertain exceptions.
Success is `binding_verified_in_adapter`; native acceptance remains pending.

Stateful synthetic regressions invalidate occurrence wrappers on each mutation,
including stale interfaces whose getters still work. They test three boundary
kinds, False Update, wrong source/binding/UUID, extra geometry, ownership loss and
native-like exceptions. This establishes orchestration against the synthetic
adapter only. The native adapter still needs explicit owned-document/path checks,
ambiguous-lookup rejection, typed getters, STA execution, and saved-copy acceptance
under exclusive CAD ownership; none of those runtime claims is inferred here.
